## 3. Portable CLI routing and cache integration

The source behavior to preserve is one universal `op` wrapper routing eligible `read`, `inject`, `run`, JSON `item get` to Connect; other commands to owner-approved direct desktop/service identity; Redis caches read/item JSON/run/inject bytes and invalidates after modeled mutations. `op-cache` treats `OP_CACHE=off` as bypass, fresh TTL 24h, stale ceiling 30d, refresh timeout 4s, mutation grace 30s, and cache outage as native CLI fallthrough. Cache keys include auth identity and output-affecting environment/argv/content. **This is a contract to port/test, not permission to copy Linux files as-is or ship the advisory `op-driver.py` as the standard.** Source implementation exists in the owner's separately managed installation; acquire/review it through authorized source control or ask owner for the implementation when on the Studio. This skill is self-contained as a procedure; no local Linux scratch path is required.

1. Audit the source helper and tests before installation. Use a portable Python 3 runtime (mise if available, otherwise a supported owner-managed Python) and official native `op`; resolve real paths from the actual host, never hardcode `/usr/bin/op`, `/usr/bin/python3`, another user's home, or rely on shebang alone. Do not run a Linux-only `op-token-sync`: it uses `readlink -f`, `sha256sum`, `/proc`, systemd/D-Bus, `/usr/bin/op`, and forces desktop auth off. Adapt a Mac entrypoint with owned config and explicit escape to native CLI. Review existing wrapper first and change only the owner-approved path. No diverging `OP_AUTH`/`OP_BACKEND` protocol is approved by this skill; if a new dispatcher is proposed, document and test its behavior against canonical read/mutation/fallback semantics before adopting it. Do not copy a different person's credentials/config.
2. `/proc` PID/start-time locking is Linux-specific. A Mac `kill(pid, 0)` fallback **does not prove process identity** (PID reuse and zombies); use portable same-owner process identity with reliable birth time and bound lease/reclaim policy, or conservatively time out/fall through to native CLI. Test signal handling, lock reclaim, TTY, SIGPIPE, mode/force semantics, Unicode/bytes, and concurrent misses on real macOS. Redis helper's URL parser supports local plain `redis://host:port/db` and Unix socket; do not assume `rediss://`, IPv6, URL-encoded auth or arbitrary TCP query authentication. Use the already deployed loopback Redis, isolated DB/prefix only after validating isolation and ACL. A Redis DB alone is **not** a security boundary.
3. Cache only identities whose output key really distinguishes account/credentials: service and Connect token hashes, or desktop with explicitly pinned `OP_ACCOUNT`/`--account` and permission-change flush. Implicit desktop account selection => bypass cache. Never cache OTP, share links, errors, unknown options, or values produced by unmodeled inputs; do not fall back to a different account when a credential is missing. Confirm route contract from installed `op` help: official Connect CLI supports only `read`, `inject`, `run`, `item get --format json`. `op item edit` is not routed via Connect CLI. Suppress inherited ambient tokens when selecting another identity; ensure supported flags and subcommands still reach native CLI faithfully. A Connect bootstrap token retrieved via service-account Redis entry needs a cold-cache fallback **independent of Connect**, a warm/restart proof and rotation path; otherwise store protected local owner-issued token. Resolve `op` in user scripts/services and verify direct native CLI still works. Never globally source plaintext secrets.
4. Start with cache disabled, test owner-native CLI, then Connect direct access, then wrapper routing, then enable cache. `op-cache stats` and `list` must show metadata only; do not expose `MONITOR`, `GET` secret values, Redis dumps, or unredacted Compose logs. On Redis outage native CLI must remain usable, subject to authentication and 1Password cloud/Connect availability. Do not stop the shared Redis just to test outage; isolate by overriding the helper URL to a closed loopback port for one process, confirm native fallback, restore URL. Verify this override actually reaches the tested wrapper and does not change production.

**Gate:** wrapper passes Mac-native tests; if port remains untested, leave native CLI as `op` and mark cache adapter pending. Do not advertise a Linux helper's passing tests as Mac acceptance.

Stop and repair on auth/permission mismatch, missing Connect eligibility, accidental plaintext, wrong identity, unexpected host bind, or installer drift.
