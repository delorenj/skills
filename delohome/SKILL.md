# DeLoHome

The house's control surface. Source lives at `~/code/DeLoHome`; it ships one MCP hub and
one CLI generated from the same tool registry, so the two cannot drift.

Almost everything here fails in a way that looks like something else. A Chromecast that
"doesn't have Netflix" is a deprecated app id. A Hue pairing failure arrives as HTTP 200.
A Z-Wave switch that refuses to pair is still bonded to a controller that no longer
exists. The references carry those findings; read the one that matches the task before
touching hardware.

## Operating principles

**Prefer the CLI.** `delohome <domain> <tool>` is generated by reflecting over the same
`DomainRegistry` the MCP server exposes, so a tool cannot exist in one and not the other.
No registration, works in any shell, and `--json` gives clean pipeable stdout. Reach for
MCP only when an agent session wants the tools resident — see
[references/mcp-setup.md](./references/mcp-setup.md).

**A panel is not a cast target.** Three different kinds of thing share a screen here, and
conflating them is the most common mistake. A *cast device* accepts media pushed to it. A
*display* is the panel itself and accepts power, input and app commands but cannot be cast
to. An *HDMI source* is a box plugged into a panel. The living room has all three at once:
the Hisense panel owns power and input, the SHIELD in it owns content, and the Xbox is a
third source on the same screen.

**Resolve the room, don't guess the device.** Pass whatever the user actually said —
"Dommy's room", "the piano", "downstairs tv" are all in the map, and matching survives
speech-to-text mangling. `delohome list-rooms` is the disambiguator. Never hardcode an IP.

**Verify before you assert.** This project's facts were established by probing hardware,
and several contradict what the docs and the wider internet say. The README is orientation,
not ground truth; `config/home.yaml` is the source of truth for what exists, and
`mise run discover` diffs it against the live LAN.


## Decision tree: which surface does this task want?

```
Does the request name a room and an outcome? ("bedroom", "cozy")
├─ It is about light           -> lights.md      -> delohome lights ...
├─ It is about a specific title or "what's on"
│  ├─ The title is in DeLoFlix -> media.md       -> delohome media play  (exact, works)
│  └─ It is a streaming service
│     ├─ Cast device in that room  -> media.md   -> open the app; a plain
│     │                                             Chromecast cannot then be
│     │                                             navigated to a title
│     └─ Panel in that room        -> displays.md-> launch the app ON the set
├─ It is about the screen itself (power, input, volume on the panel)
│                               -> displays.md   -> delohome displays ...
└─ It is about a box plugged into a screen (Xbox, PS5, SHIELD)
                                -> displays.md   -> NOT YET WIRED: hdmi_input is
                                                    null until a panel is paired
```

## Commands

The CLI mirrors the tool registry exactly. Required parameters are positionals in schema
order; optional ones are flags. Booleans are `--on` / `--no-on`, never a bare flag,
because several tools distinguish false from unset.

```bash
delohome                                        # list domains
delohome lights                                 # list that domain's tools
delohome lights set-lights bedroom --on -b 40 -k 2200
delohome lights activate-scene 'Savanna sunset' --room bedroom
delohome media play 'The Big Lebowski' dommy
delohome media now-playing
delohome displays display-status bedroom
delohome lights list-lights --json | jq -r '.hue[] | select(.light_count>0) | .house_room'
```

Repo tasks, for the things the CLI deliberately does not do:

| Need | Run |
|---|---|
| Pair the Hue bridge | `mise run hue:pair` |
| Capture + pair the bedroom Samsung | `mise run samsung:capture` |
| Re-verify every Cast app id | `mise run verify:appids` |
| Diff the LAN against the house map | `mise run discover` |
| Generate the Z-Wave S2 keys (once, ever) | `mise run zwave:keys` |

## Credentials

Resolved environment-first, then 1Password, never written to disk. References are by
**item UUID**, not title: titles are not unique in `DeLoSecrets`, and a title containing
parentheses cannot be resolved by an `op://` reference at all — `op read` returns an empty
string and a bare error, which then surfaces as a baffling 401 from whatever service you
were actually trying to reach.

## Out of scope

- **Nanoleaf panels** — driven by `~/.config/zshyzsh/scripts/nanoleaf.sh`, not DeLoHome.
- **Host, container and network conventions** — `delonet-conventions`.
- **33GOD platform work** — `33god-hub`.
- **Xbox and PS5 power control** — modelled in the house map, no client implemented.
